# Phase 30 — RD database read-only gate

## Decision

The RD database slice is already integrated for the read-only consumer exposed
by `GET /api/rd-db`. The endpoint is backed by the canonical JSON/YAML stores
through `flujo.rd.panel.datos_panel`; `data/rd.db` is a matching regenerable
projection and is not used as the public panel source. No source adapter, data
rebuild or migration is justified by this gate.

The sibling field-data database is deliberately not promoted: `data/rd_datos.db`
exists as a zero-byte file with no SQLite objects. Calling
`flujo.rd.datos.conectar()` or `informe.resumen_json()` on it would create and
commit a schema, so those calls are excluded from this read-only phase. The
public field-data summary remains a separate, explicitly unavailable/degraded
contract until real ingestion is authorized.

## Vertical contract

```text
flujo app -> web.hub -> GET /api/rd-db -> rd.panel.datos_panel
                                      |-> data/productoras/*.json
                                      |-> knowledge/venues/*.yaml
                                      `-> knowledge/logos/* (existence metadata only)
```

`GET /api/rd-db/logo` and the upload route are outside this slice. No logo
bytes were requested, no files were uploaded and no mutating endpoint was
called.

## Mutation boundary and rollback

Before the runtime check, the protected set was recorded as the source/data
files, both database sizes and mtimes, the hub modules and the logo tree. The
runtime action is a temporary in-process `ThreadingHTTPServer` on
`127.0.0.1:<ephemeral>` and one GET request only. It is stopped, closed and
joined in the same foreground command. Rollback is therefore server shutdown;
if any protected file changes, the gate fails and no integration edit is
allowed. The existing canonical readers and projection remain the rollback
path; no database rebuild is permitted here.

## Risks and next action

- `rd.db` can be regenerated by `build_rd_db()`, which unlinks and rewrites
  the projection; that operation was not called.
- `rd_datos.db` is an empty field-data store. It must not be silently seeded;
  real ingestion needs a separate authorized slice with privacy and rollback
  evidence.
- Productora contact fields such as Instagram are intentionally excluded by
  `datos_panel`; logo preview/upload remains outside this gate.

The GET passed, so this read-only slice is integrated and the next bounded
consumer is the ISKVW SVG visualizer/index. If a later visualizer gate fails,
preserve the existing static resolver and classify the route as partial; do
not copy or rewrite the SVG/artwork tree.
